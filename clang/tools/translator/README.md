# DACPP Translator

`clang/tools/translator` contains the DACPP source-to-source translator built
on top of Clang. In the current single-node release branch, the practical
workflow is centered on translating DACPP programs into `buffer`-mode SYCL
source files and then compiling them with a SYCL toolchain.

## Upstream Base

This translator release is based on the LLVM/Clang 19.1.4 source tree.

## Build

Build the translator from the repository root:

```bash
cmake -S llvm -B build -G Ninja \
  -DLLVM_ENABLE_PROJECTS="clang" \
  -DCMAKE_BUILD_TYPE=Release
ninja -C build translator
```

The generated executable is:

```text
build/bin/translator/translator
```

## Current Translation Workflow

This release branch targets the `buffer` workflow.

- `examples/auto_test.sh` translates DACPP examples into `*_sycl_buffer.cpp`
- `scripts/dacpp_translate.sh` generates `*_sycl_buffer.cpp` for user-written
  DACPP programs
- the active rewriter sources in `CMakeLists.txt` are the buffer-mode files

If you are using this branch as a release version, prepare DACPP programs for
the `buffer` translation path.

## Examples and Automatic Testing

The `examples/` directory contains representative DACPP kernels such as matrix
multiplication, stencil, jacobi, wave equation, DFT, and others.

The main regression driver is:

```text
clang/tools/translator/examples/auto_test.sh
```

This script performs the following steps for the built-in examples:

- translates DACPP source files into `*_sycl_buffer.cpp`
- compiles reference SYCL or serial baseline programs
- compiles the generated SYCL files
- runs the executables and compares their outputs against the reference results

Typical usage:

```bash
cd clang/tools/translator/examples
bash auto_test.sh
```

By default, `auto_test.sh` runs CPU-oriented SYCL compilation.

Supported scale options:

- `--small`
- `--large`

Supported device options:

- `--cpu` (default)
- `--gpu`

Examples:

```bash
bash auto_test.sh
bash auto_test.sh --large
bash auto_test.sh --gpu
```

Temporary files generated during testing are written to:

```text
clang/tools/translator/examples/tmp/
```

## Translating Your Own DACPP Program

For user-written DACPP programs, use the helper scripts in `scripts/` instead
of reusing `examples/auto_test.sh`.

Translate a DACPP source file:

```bash
clang/tools/translator/scripts/dacpp_translate.sh /path/to/my_case.dac.cpp
```

This generates:

```text
/path/to/my_case.dac_sycl_buffer.cpp
```

Build the generated SYCL file:

```bash
clang/tools/translator/scripts/dacpp_build.sh /path/to/my_case.dac_sycl_buffer.cpp
```

By default, `dacpp_build.sh` performs a CPU-oriented SYCL build. For NVIDIA GPU
targets, use:

```bash
clang/tools/translator/scripts/dacpp_build.sh /path/to/my_case.dac_sycl_buffer.cpp --gpu
```

## Environment Notes

- `examples/auto_test.sh` expects a built translator under `build/bin/translator/translator`.
- `examples/auto_test.sh` uses `icpx`. If `icpx` is not already on `PATH`,
  set `ONEAPI_ROOT` so the script can source `ONEAPI_ROOT/setvars.sh`.
- `examples/auto_test.sh` defaults to CPU-oriented SYCL compilation.
- `examples/auto_test.sh --gpu` requires `CUDA_HOME` to be set.
- `scripts/dacpp_build.sh` is more flexible: it defaults to CPU mode and
  supports `--gpu`, `CUDA_HOME`, `ONEAPI_ROOT`, and `ICPX` overrides.
